# Shared shell (all pages)

**Scope:** Everything that wraps or is reused by the ten question-led views (V1–V10) and the Session drill-down: App shell, navigation, header, filters, URL state, panel frame, chart/table primitives, format helpers, harness-scope rules, the Bun server (`/api/*`, static assets, security), the ClickHouse client (snapshot vs live), and the registry-driven contributor chips and info notes. Per-view content is audited in the per-page files.
**Files:** `dashboard/src/App.tsx`, `app-parts.tsx`, `app-data.ts`, `app-state.ts`, `routes.tsx`, `routes-health.tsx`, `routes-outcomes.tsx`, `harness-scope.ts`, `components.tsx`, `charts.tsx`, `format.ts`, `contracts.ts`, `tokens.ts`, `styles.css`, `main.tsx`; `dashboard/server.ts`, `server/clickhouse.ts`, `server/pipeline.ts` (route counts, contributions), `server/views.ts` (window/harness filter helpers only); registry tables `facts_sql/002_registry.sql`, loaded from `facts_sql/signal_support.toml` by `facts install`. Server query keys: none of its own except the registry batch (`signals`, `support`, `routes`, `strays`, `exclusions`, `harnesses`, `server.ts:129-158`) and the route-count batch (`spans`, `logs`, `hooks`, `pipeline.ts:82-97`). Fact views: `introspection.spans` / `introspection.logs` (tables, `001_tables.sql:7,28`), `introspection.hook_rows` (`003_views.sql:757`), `introspection.harnesses` and the four `signal_*` tables (`002_registry.sql:5-84`).

## Behaviours to preserve

- Time range: presets are live. The URL carries `range=<days>` and the window is recomputed to end now on load, on Refresh and when a link is reopened; a custom range carries absolute UTC `start`/`end` and never moves. Editing a custom input turns a preset into a custom range. The default with no parameters is the live Last 7 days.
- Custom range: two UTC `datetime-local` inputs at minute resolution; each edit navigates; seconds forced to `:00.000Z`; server limits: both RFC 3339 UTC with `Z`, `start < end`, span ≤ 92 days.
- Harness filter: empty = All = union of ENABLED harnesses only; a specific harness must be enabled; filters are applied in SQL by `introspection.harnesses.enabled` (so disabled-harness rows never reach any view). Colour follows harness, never rank.
- View navigation and Session links carry the range (`range`, or `start` and `end`) and `harness`; Session link replaces `harness` with the row's harness, and the Session page keeps that harness in its URL (the next nav click narrows to it).
- Not emitted vs not applicable: not applicable (e.g. Codex exec for interrupts) renders the panel with "Not applicable" + registry note when ALL selected harnesses are n/a, and chip state "not applicable" otherwise; not emitted by any enabled harness hides the whole signal (panel absent) and lists it under hidden signals on Pipeline. Single-harness selection never shows zero for n/a.
- Info content only on hover/focus/click: popover text (title, question, formula, per-harness alignment, route description, note, row count), chip native `title` tooltips (rows and route start day), BarList native `title` ("value" or "No value"), chart readout tooltip and per-day aria-labels, `aria-label` "Definition of `<title>`". A redesign must keep all of these reachable by keyboard.
- "View as table" disclosure is the accessible, exact-value alternative to every chart; default closed.
- Empty states: charts and tables say "No rows for the selected range." (tables may override); KPIs use "—" (null never 0); chart gaps are visible days, not interpolated.
- Status line: Loading… / Query failed / Queried HH:MM:SS UTC · N ms (Session: no ms). Failure message is shown verbatim from the server (`error`); failure also blanks the view.
- Registry failure outranks view failure; the registry is loaded once per page; the page renders nothing but header until the registry is present.
- Time zones: window and shell timestamps are UTC; chart `day` keys are date strings and are treated as UTC by gap filling (some views group by `Europe/London` in SQL, see their pages).
- Focus: heading focus on title change; skip link; focus-visible outline everywhere.
- Security: loopback only, Host/Origin checks, GET/HEAD only, CSP forbids inline script/style, ClickHouse local-address assertion and `readonly=2`.

## Audit notes

- `sessionHref` copies the current filters and then overrides `harness` with the row's harness (`App.tsx:35-36`). On the Session page `readFilters()` therefore sets `filters.harness` to that harness, and the nav links back to a view carry it, narrowing the next view. Likely unintended side effect; unverified.
- The Session page has no filter bar and `/api/session` ignores the range, but the range stays in the URL only to be carried back.
- Info-note row counts show "0 rows" when `contributions` has no entry for a signal (`components.tsx:170,183`: `rows ?? 0`), which is indistinguishable from a true zero; contributions exist only for the current view's visible harness-scoped signals (`pipeline.ts:281-283`). Panels that cite another view's signal would show 0.
- `NotEmittedNotice` named in the audit brief does not exist; code has only `NotApplicableNotice`. "Not emitted" is handled by hiding signals (`Panel` returns null), so a redesign that adds a per-panel "not emitted" message would be a behaviour change and would need the Pipeline hidden list to stay.
- The registry is fetched once per page (`loaded` ref) and cached 60 s server-side: enabling/disabling a harness or reinstalling the registry is only reflected after a full reload. High risk to forget when moving data-loading.
- `maybe("abc")` returns 0 (via `num`), not null, so a non-numeric string renders as 0 instead of "—"; `ratio` returns null for a negative denominator. Unverified whether any view feeds such values.
- `fmtCount` rounds negatives like `-0.4` to `-0` (Intl output "-0"); `fmtSeconds(59.96)` prints "60 s"; `fmtSeconds(9.96)` prints "10.0 s". Minor rounding quirks.
- DailyChart clips values above `max` silently (`Math.min(amount, top)`); line charts draw isolated days as dots; stacked charts hide zero-value parts, so a series with only zeros is invisible in the chart but in the legend and tooltip.
- `continuousDays` treats `day` strings as UTC midnights even for views that group by `Europe/London` (a pure date label, so harmless today but worth keeping consistent).
- `Panel` is not rendered when `signals[0]` is hidden, but a KPI or chart built from a derived value still computed in the view may show a number without a panel context; check per page.
- Registry `unit` and `view_title` are loaded but only `view_title` is used (Pipeline); `unit` is not displayed anywhere.
- Server: `localhost:4173` is rejected (hostname must be exactly `127.0.0.1`); asset responses have no `cache-control`; JSON errors from ClickHouse become 503 with the ClickHouse error text surfaced verbatim in the UI.
- `elapsedMs` includes registry wait and route-count scans, so it overstates the SQL cost of the view itself.
- Highest risk of loss in a redesign: hover-only content (info popover, chip tooltips, BarList `title`, chart readout), the Contributors chips and their state vocabulary, the hidden-signal mechanism, live presets (`range` in the URL), "View as table" parity, skip link and focus-on-heading, Host/Origin checks and CSP.
