# Pipeline (V1, `/pipeline`)

**Question:** Is the fact loader fresh, complete, and correct for every harness? (`dashboard/src/routes-health.tsx:14-15`)
**Files:** view `dashboard/src/views/Pipeline.tsx` (below `P:`); server `dashboard/server/pipeline.ts` (`S:`), `dashboard/server.ts` (`SV:`: view handler 373-407, inbox 64-73, registry 129-158), `dashboard/server/clickhouse.ts` (`CH:`), `dashboard/src/harness-scope.ts` (`HS:`). Pipeline is NOT in `VIEW_QUERIES`; it has its own datasets from `pipelineData` (`S:619-659`): `loaders, freshness, parity, recombination, sanitization, daily_rows, coverage, unrouted, project_coverage, project_rejections, project_sync, strays, exclusions, hidden`. Fact views and tables used: `introspection.spans` (`001_tables.sql:7`), `logs` (`:28`), `session_projects` (`:51`), `hook_events` (`:71`), `hook_rows` (`003_views.sql:757`), `usage_events` (`003:6`), `task_outcomes` (`003:83`), `model_calls` (`003:354`), `tool_calls` (`003:455`) read through their `_snapshot` tables (generated in `facts.py:207`) or live views when the window starts before the snapshot horizon (`CH:141-154`, `SV:380-382`); raw SigNoz tables `signoz_traces.distributed_signoz_index_v3`, `signoz_logs.distributed_logs_v2`; ClickHouse `system.view_refreshes`; registry tables `introspection.signals/signal_support/signal_routes/signal_strays/signal_exclusions/harnesses` (`SV:129-143`). Registry signals: `signal_support.toml:321-391`. Shared shell (KPI/Panel frames, info footers, Contributors chips, filters, status chip) is audited by the SHELL page; panel `signals={[...]}` props feed each info footer.

Filter semantics in one place: the time-range filter reaches only `daily_rows`, `recombination`, `project_coverage`, `project_rejections`, `unrouted`, route counts (coverage) and part of `parity`; `loaders`, `freshness`, `sanitization`, `project_sync`, `strays`, `exclusions`, `hidden` ignore it. The harness filter is applied in the browser (`inScope`, `P:158-159`) to freshness, parity, coverage, daily, project_coverage, strays, unrouted; it is NOT applied to loaders, sanitization, recombination, project_sync, project_rejections, exclusions, hidden. `daily_rows` is additionally filtered on the server by enabled harnesses and the selected harness (`inWindow`, `views.ts:25-34`).

## Behaviours to preserve

- UTC everywhere: daily rows use `toDate(ts)` in UTC; parity window and last-success/last-sync/source-latest strings are UTC; freshness is relative to the server clock. No Europe/London logic on this page.
- Time range ≠ everything: freshness is always "last 1 day", loaders and sync are current, sanitization is all-time, strays/exclusions/hidden are registry; parity is capped to the last 7 days of the window and ends 10 minutes before now; the parity subtitle shows the effective window.
- All = union of enabled harnesses; a selected harness must be enabled (otherwise HTTP 400). The coverage grid, however, lists every known harness column for All so disabled harnesses show "not in use" and rows on a disabled harness's route are flagged "not in use, rows present".
- Coverage states are never replaced by zero: not applicable is not zero; silent route states split by whether the harness is otherwise active and whether the route is `expect=events`.
- Coverage grid hides signals hidden on this machine; those are listed in "Signals hidden on this machine". Excluded signals listed separately.
- Unrouted: top 40 by row count; harness "" means an unresolved Codex hook; harness filter drops it (harness "" ≠ selected).
- `Match` compares cached and output tokens as well as operations and input, but only ops and input are displayed.
- Native `title` on every coverage chip (route, own, foreign, unexplained) is the only place those counts appear; the legend chips have no title.
- "no facts" replaces lag whenever SigNoz has rows but facts have none (never a fake lag); KPI carries the source count.
- Hook inbox backlog is read from the local filesystem at request time, not from ClickHouse; missing directory = 0.
- Snapshot vs live: windows starting more than 91 days ago read live fact views instead of `_snapshot` tables for recombination, parity facts and project coverage.
- Route counts are cached 60 s per start|end key, so coverage can lag the loaders by up to a minute.
- Fact-rows-per-day keeps continuous UTC days (gaps visible); table view toggle exposes exact values.
- Tables use shared DataTable limits (340px scroll, numeric right aligned, null → "—"); a redesign must keep full row access for long coverage grids and the 40-row unrouted list.
- No links out to Session or other views from this page.
