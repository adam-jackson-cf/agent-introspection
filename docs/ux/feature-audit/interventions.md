## Behaviours to preserve

- Time range: only the three ClickHouse datasets, the comparison-table inclusion test (strict inside start/end) and the window clipping use it; findings, proposals, history and all four KPIs ignore it (`IV:262-267`, `SV:246-281`).
- Snapshot vs live: datasets read `_snapshot` tables when the window start is within 91 days of now, else the live views (`SV:380-394`, `clickhouse.ts:141-154`). Workflow data is always read fresh from SQLite per request, read-only (`SV:231`).
- Harness filter: ClickHouse side filters by SQL (`HARNESS_FILTER` includes enabled-harness check, `VQ:28-37`); store side filters in the browser by `metric_harnesses ?? harnesses`; rows lacking both appear under All only. An unknown/disabled harness is rejected 400 (`SV:415-419`).
- Time zones: baseline and window days are Europe/London (`VQ:413,417,423`, `IV:24-27`); displayed timestamps (`Applied`, `Last seen`, `When`) are UTC sliced to minutes; store timestamps are ISO UTC from `*_ns`, `created_at` strings as stored.
- Window rule: the application day is excluded from both windows; windows are equal in whole London days; shorter side wins; 0 days is a valid state.
- "Recorded" verdict/ratio/rates are written by `facts sync` events and shown verbatim; the page never recomputes a verdict. The computed before/after table and the recorded ratio sit side by side and can disagree.
- "not evaluated" is shown for null verdict in two tables; "free text (legacy)" for non-object metrics; "not recorded" for null tier (tier table only; Tier columns show blank).
- Panel info text: formula strings per `intervene.*` signal; the Proposals KPI shows the tier-audit definition, the Applied KPI the post-recurrence one.
- Decision history reason is limited to whitelisted scalar fields, max 200 chars (privacy: raw payload never read) (`SV:269-281`).
- Excluded signal `intervene.rule_adherence` is intentionally never displayed.
- Tables clip at the shared 340px scroll box with no "N of M" note (`charts.tsx` DataTable; baseline defect).
- Empty-state wording above includes a CLI hint (`agent-introspection candidates export`) that a redesign could drop.
- The Findings subtitle "(7 Europe/London days)" is fixed text and does not follow the range select (baseline defect, still present, `IV:384`).

## Audit notes

- "Tasks" means different things within one page: Active findings Count/Tasks/Days read store fields (`occurrence_count`, `canonical_task_count`), whereas the Practice table's "Tasks" column reads `impact` (the correction finding's task count) and "Sessions" reads `subject.sessions`; names collide with INTV-S13 "Tasks before/after" (all tasks or labelled tasks).
- The baseline chart's "failures per 100 tasks" divides all-cluster failures by all tasks, while the per-row comparison uses one cluster over all tasks; the chart cannot be used to read any row's before/after.
- Applied KPI counts every applied proposal (all dates), the comparison table only those applied strictly inside the range: counts disagree by design with no visible explanation.
- Daily cluster/correction series are range-limited, so for an intervention close to a range edge the window is clipped; the table states `days` but no reason.
- ClickHouse SQL and the browser compute the cluster rule separately: store findings use the sync's cluster rule; `cluster_daily` has no threshold, it sums every failure group. Possible mismatch between a finding's own counts and the table's matched counts [INFERENCE, unverified].
- Task types column renders an array through DataTable's default cell (`IV:544`); the rendering of arrays (comma list vs object string) was not verified.
- The Proposals KPI info note describes tier audit, not proposal states; Applied detail verdict counts ignore null verdicts, so the three numbers can sum below the headline.
- First-seen is queried (`SV:249`) and never displayed (possible dropped signal).
- High risk of being dropped in a redesign: Approval history (newest, no baseline row), the recorded-vs-computed pair in the recurrence table, window-days and excluded-application-day rule, "not evaluated"/"free text (legacy)" fallbacks, the CLI hint in the empty Proposals text, 200-char reason truncation, and the harness fallback for rows lacking a harness list.
- UI-heavy: all counts and the full before/after algorithm run in the browser; moving to source requires the SQLite store logic to join ClickHouse daily data, which are in different stores.
