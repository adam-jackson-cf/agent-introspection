## Behaviours to preserve

- Time range and harness apply to every query through `inWindow("ts")`; harness "All" = union of enabled harnesses only (`introspection.harnesses.enabled = 1`), never a hard-coded list (VQ:25-34).
- Windows that start before the snapshot horizon (90 days + 1) are re-queried against the live fact views (`dashboard/server/clickhouse.ts:144-154`; `dashboard/server.ts:378-394`); a redesign must keep reading the same table family.
- All is built in the browser from per-harness rows (numerators and denominators summed, ratio taken last): utilization is token-weighted, never an average of per-harness percentages. By harness panel subtitle says "All above is their sum".
- Days are UTC calendar days (`toDate` on a UTC column). Session "Last seen" is explicitly labelled UTC; only 16 characters (to the minute) shown.
- Sorting: By harness by harness name; By model by input descending, LIMIT 40; Sessions by (input − cached) descending, LIMIT 20; daily series ascending by day. There is no client-side sort control.
- Cache-creation handling: when any enabled harness cannot emit it (Codex), the signal is hidden machine-wide: no Cache writes column, KPI detail switches to "P% of input". Conversely with only Claude Code/omp enabled it appears.
- Hidden vs not-applicable: a panel whose first signal is hidden is removed entirely; a not-applicable first signal swaps the body for the registry's reason, never zero.
- Panel info popover (hover, focus, click; Escape closes) carries the definition, formula and per-harness route/alignment/notes/row counts. This is the only place alignment ("aligned/differs") is visible; a redesign could silently drop it.
- Contributor chips carry native `title` text (rows on route, route start day) and coverage states.
- Session link carries the current range and harness filters plus `harness` and `session` params.
- Chart tooltips and per-column aria-labels; "View as table" fallbacks under both charts expose exact values.
- Empty state text: "No rows for the selected range." for both tables and charts.
- Not-emitted for Codex cache writes; Claude Code input includes cache-creation tokens (affects utilization denominator).

## Audit notes

- `models` query returns `creation` (VQ:139) and `sessions` returns `first_seen` (VQ:143) that the UI never displays; the By model table has no Cache writes column although By harness does.
- By harness "Sessions" and "Operations" (and By model "Operations") render through the default cell (max 2 decimals, no compact format), unlike other counts that use `fmtCount`; display inconsistency.
- The By harness "Sessions" column sums per-harness unique session counts for the KPI; fine because session IDs are harness-scoped, but the By model/By harness panels do not de-duplicate sessions that used multiple models.
- Uncached input for omp and Claude Code includes cache-creation input (registry notes); "Uncached" therefore is not "never cached" for those harnesses. This is carried only by the popover note.
- Utilization denominators differ by harness definition (Claude Code input = input + cache_creation + cache_read), so cross-harness utilization comparison is not like-for-like; surfaced only in the popover.
- The By model LIMIT 40 is invisible to the reader; the panel gives no "top 40" subtitle.
- Top-20 sessions panel's measured signal (`usage.uncached_input`) is used for hiding/not-applicable logic; a hidden first signal removes the panel.
- High drop risk: the info popover (alignment per harness), contributor chips, the conditional cache-writes column and KPI detail switch, "View as table" fallbacks, the 0-100 axis clamp, and the Session link filter params.
- Utilization chart series list comes from the selected harnesses, so a harness with no data still has a legend entry and an empty table column.
