## Behaviours to preserve

- Time range filters on `start_ts` for kpi, daily, tasks and, since 2026-10-01, for recovery too (calls are included when their task started in the window); harness filter is enabled-harness ∩ selection; All = union by summing numerators/denominators (never averaging rates).
- Not-emitted components show "—", never 0; counts use `count(col)` so NULL rows leave the denominator. Component cells use their own denominator, KPI detail states it ("tasks that observe it").
- Clean completion counts only components the harness observes (subtitle states this); codex_exec is excluded from interrupt/steer/follow-up/clean (registry `not applicable`) and excluded from `friction.tasks` flags as NULL.
- Recovery is inferred; KPI text includes "(inferred)". Recovery unit is (task, operation), with operation = tool + command head + subcommand; only tasks with attributed `task_id`.
- Daily interrupt/steer chart sums across selected harnesses, not per harness; a task with both counts in both lines (subtitle).
- Latest tasks: only tasks with interrupted/steered/errored =1, newest first, top 25; the Follow-up flag is shown but is not part of the filter.
- Top-N limits: operations 25 (with "Showing N of M" when cut), latest tasks 25 (no notice).
- Links: Session column → `/session` with harness and session id; text = 8-char prefix + "…".
- Time zone: UTC for daily buckets and Started (UTC) (`toDate(start_ts)`); no Europe/London.
- Hover/focus-only: info popover with registry formula and per-harness route notes (the harness-specific inference caveats such as Claude Code interrupt = missing Stop hook live only here); contributor chip titles; table-view disclosures; chart hover readout.
- Not-applicable panel replacement and hidden-signal suppression as in shared `Panel`.
- Panel subtitles carry the definitions (— means not emitted; recovery definition; steer/interrupt overlap) and must survive any redesign.
