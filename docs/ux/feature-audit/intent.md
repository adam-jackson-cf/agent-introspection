## Behaviours to preserve

- Filters: time range is the UTC window on task start (`start_ts`), harness All = union of enabled harnesses; the series list follows the selected harnesses; the By-harness table shows only harnesses that have task rows.
- All = sum of numerators and denominators, never an average of rates (`Intent.tsx:126`, `C07`, `C08`).
- `codex_exec` is excluded from next-prompt numerators and denominators (corrected, frustrated, correction kinds, effort payoff corrected and clean), the repeated table and the recent table; it stays in `tasks`, labelled and task types (`views.ts:57,122-123`).
- Next-prompt rules live in the fact view: the next labelled prompt after the task end, within 10 minutes, correction probability >= 0.5; tasks in sessions with no labelled prompt have NULL flags and so stay out of the denominator (`003_views.sql:695-752`).
- Sorting and limits: task types in classifier order; correction kinds A-Z; effort payoff by type then effort ordinal; repeated table tasks desc then project A-Z, unlimited; recent table newest first, 25 rows; tables clipped at 340px (`styles.css:576-579`).
- Time zones: all intent datasets use UTC dates (`toDate(start_ts)` for the daily series, UTC strings for times); Recurrence/Interventions use Europe/London - do not mix when merging pages.
- Links: the Session link carries the current start, end and harness filter plus the row's harness and session id to `/session` (`App.tsx:35-36`).
- Labelled data exists only from the prompt-export start (2026-09-30); earlier prompts were redacted, so low labelled shares are expected (registry note in info popover).
- Only on hover/focus: info popover (question, formula, per-harness alignment/route/notes/row counts), chip `title` text, bar-row `title` count, chart day tooltip, "View as table" detail toggles (all five charts/bar lists have a table twin).
- Evaluation workspaces are excluded from the repeated-corrections and recent-corrected datasets (`views.ts:429,436`).
- Empty states: repeated and recent tables have custom messages; bar lists have none.

## Audit notes

- `Repeated corrections` KPI is registered under `intent.correction_kind` (unit tasks) while it counts project × kind pairs; neither the registry formula nor the SQL defines the ≥2 tasks and ≥2 sessions rule, which lives only in `Intent.tsx`.
- Repeated-corrections table lists singleton pairs too (every project × kind) while only the KPI applies the repeat threshold; the table has no highlighting of which rows are repeats.
- The project requirement (INNER JOIN with a non-empty project) applies only to the repeated table; `recent` uses LEFT JOIN so projects can be blank ("—").
- Correction kinds sort alphabetically, not by size, and the bar lists have no empty message; with no data the panel body is blank.
- Daily corrected rate uses UTC days while Recurrence and Interventions use Europe/London days, so the same corrected task can fall on different days across pages.
- Effort payoff mixes `effort.level` semantics: Claude Code efforts before 2026-09-28 are mostly `unset` and `mixed` means several efforts in one task; `unset` is the provider default, not no reasoning (registry formula for effort.level). The panel lists efforts as strings with no colour ramp even though `EFFORT_COLOR` exists.
- The `Session` column shows only 8 characters of the id; the full id is not visible anywhere on hover (only in the link target).
- Task type "continue" and unknown types: `typeRank` puts unknown types after the eight known ones; unknown types still display.
- High drop risk: the By-harness table (only per-harness numerator/denominator view), the Session drill-down link, the effort-correlation caveat, the "View as table" twins for every chart, the per-harness detail string under task-type bars, the ≥2/≥2 repeat rule and the evaluation-exclusion statement, and the info-popover registry notes (labelled-from date, omp extension note).
