## Signals and how they are formed

Shared SQL context: task rows window on `start_ts` (`task_outcomes.start_ts`); usage rows on `ts` (`usage_events.ts`); both DateTime64(9,'UTC'), days via `toDate(...)` therefore UTC. Harness filter and snapshot/live rule as on the Cache page (`views.ts:28-34`, `server.ts:378-394`). Harness support lists codex (CLI, app-server, exec) / oh-my-pi / claude-code. "Task" = a Codex turn, an OMP root run, or a Claude Code interaction (`UV:83-347`; ST:541-543).

## Behaviours to preserve

- Time range and harness feed every query; All = union of enabled harnesses and is recombined in the browser from per-harness numerators and denominators.
- Two different windows on the same page: usage-based reasoning rows window on `usage_events.ts`; task rows on `task_outcomes.start_ts`. Claude Code reasoning comes only from task rows (never double counted: usage branch excludes `claude-code`).
- Days are UTC. Top 25 "Started (UTC)" is truncated to the minute.
- "Unset means the provider default, not no reasoning" and "Correlational" caveats, "≥ 3 tasks" threshold note, and "Noisy on low-volume days; a friction proxy, not a quality score" are subtitles that carry meaning and must survive.
- Sorting rules: outcomes and spend tables by harness then effort rank; Model × effort by harness, model, effort (string order); Top 25 by reasoning descending; LIMIT 25. Model × effort is filtered by `HAVING tasks >= 3` in SQL.
- Percent cells show "—" (never 0) when the denominator is empty; reasoning cells show "—" when no task reported reasoning; clean cell yes/no/—.
- Mixed effort: tasks with more than one effort in a run are labelled `mixed`, never counted as heavy.
- Effort chart series are limited to the efforts present in the returned rows; legend hidden for a single series.
- Session link in the Top 25 table carries range, harness filters, `harness`, `session`.
- Popover definitions with per-harness alignment (e.g. Claude Code reasoning is per turn from the Stop hook, only since the hooks were installed) are only visible on hover/focus; chip tooltips show rows on route and route start day.
- `task.delegations` ("Delegations per task") is shown in the outcomes table as "Delegations / task" (`Effort.tsx:260-270`; `outcomes.delegations`, `delegations_den` at `views.ts:154`).
- Not-applicable and hidden rules: a panel whose first signal is hidden is not drawn; not-applicable shows the registry reason instead of zero.

## Audit notes

- Reasoning share has three populations under one registry id `effort.reasoning_share`: KPI and spend table (same usage rows) and outcomes table (task-attributed). They differ by design (ST:587); see Fixed.
- `ratio(totalReasoning, spend.output)` pools Codex/omp per-call usage with Claude Code per-turn task totals (a documented "differs").
- Daily clean completion, task mix and median duration (`daily_tasks`) are not grouped by harness, so they mix harnesses with different effort coverage and clean-observation sets; the daily median is a pooled quantile, not a combination of per-harness medians (VQ:159-162).
- The daily duration table (`Object.values(durationDaily)`) is unsorted while the chart rows are sorted; order matches only because the query orders by day (ET:172-174,188).
- `outcomes` also selects `steered_n/steered_den`; `friction.steer` has no display here. A redesign should not read this as intent to drop it without decision.
- Claude Code reasoning exists only since the activity hooks were installed, and effort is mostly `unset` before 2026-09-28; the only on-page statement is in the popover/subtitle.
- Highest drop risk: popover definitions with per-harness alignment, contributor chips, the correlational / unset / noisy caveat subtitles, the ≥ 3 task threshold, "—" semantics, effort ordering and colour ramp, the Top-25 session link.
