## Behaviours to preserve

- Filters: the time range is a UTC window (`start <= ts < end`) applied to every dataset except `actionable`, which ignores the start and uses the 7 Europe/London calendar days ending at the window end; harness "All" = union of enabled harnesses (`harnessFilter`), a single harness restricts every query and the series list (`views.ts:28-37,126-127`).
- Clusters (RECUR-F09/F10) are cross-harness: thresholds apply to the cluster totals over all selected harnesses, then the table shows one row per cluster with a per-harness breakdown. With a single harness selected the totals are for that harness only.
- Sorting/limits: clusters top 30 by tasks then occurrences; targets top 30 by tasks then calls; concentration top 200 by occurrences; tables otherwise unsorted client-side and clipped at 340px with a sticky header and no "N of M" note (`styles.css:576-605`).
- Time zones: all daily/day counts and the actionable week are Europe/London; "Last seen" and the window-end label are UTC.
- Evaluation workspaces (project_root or failure_signature under a temp directory) are excluded from failures-based datasets (`clusters`, `cluster_summary`, `actionable`, `daily`), not from `targets`, `target_summary` or `concentration`.
- Non-emitted handling: contribution chips and the info-popover rows tell the user which harness has no route/rows; hidden signals suppress whole panels; "not applicable" replaces the body; a null ratio shows "—", an empty table shows its empty text.
- Only on hover/focus: info popover content (question, formula, per-harness alignment and route rows with live row counts) and chip `title` text; table cell text such as the full signature is not truncated. Chart day tooltip is hover/focus only.
- No link leaves this page: there is no Session link on any Recurrence row (unlike Intent).
- Cluster identity is `tool_family × failure_class` (class = signature with quoted values and paths generalised), so the same failure on different files is one cluster (`003_views.sql:455-480`).

## Audit notes

- `concentration` uses raw `failure_signature` (not the generalised `failure_class`) and does not require a task id, so its "signature" is not the same unit as a cluster despite the registry calling both recurring signatures. Rows with fewer than 3 occurrences are dropped, which shifts the localized share.
- `recur.signatures` is the registry signal for four different measures (KPI clusters, clusters table, daily chart, summary denominator) and `recur.project_concentration` has a registry unit of `%` but the table also shows counts.
- The 80% localized threshold, the 30/200 limits and the actionable thresholds' UI wording are duplicated between `views.ts`, `Recurrence.tsx` and registry text; the 80% constant is not in the registry formula.
- `daily.clusters` is queried but unused; harmless but a redesign should not assume a clusters-per-day trend exists.
- `Recurrence.tsx` cites "Days" for clusters as the cluster's own distinct London days (all harnesses), while per-harness rows carry their own `days` that the UI ignores.
- Table clipping at 340px with `overflow-wrap: anywhere` (`styles.css:576-605`) hides rows beyond the fold with no "N of M" notice; failure class text can break mid-word.
- High drop risk: the harness breakdown cell (RECUR-F13), the info-popover per-harness route/alignment rows with row counts (RECUR-F14), the "from `<date>`" chip text (RECUR-F15), the actionable empty-state sentence, the evaluation-exclusion subtitle (RECUR-F23), and the two different windows (selected window vs 7 London days) which are only explained in subtitles.
