## Behaviours to preserve

- Time range: start/end sent as ClickHouse params; every query filters `ts >= start AND ts < end` (UTC, `views.ts:22-34`). Windows older than ~91 days read live fact views instead of snapshots (`server.ts:377-394`).
- Harness filter: server returns per-harness rows restricted to enabled harnesses AND (All or the selected one); All = union of enabled harnesses summed in the browser (`views.ts:25-34`). Chart series list = selected harnesses (all enabled when All).
- Hidden-signal semantics: a panel/KPI whose first signal is hidden is not rendered; KPI slot 2 swaps between Sandbox denials and Approval decisions. A redesign must keep both outcomes.
- Panel-level info popover (hover, focus, click; Escape) with registry definitions, formula and per-harness route, alignment, note, and row count. This is the only place the formulas and per-harness caveats appear. Contributor chips carry native `title` text.
- Sorting/limits: decisions n desc (no limit); sandbox n desc LIMIT 30; bypass_calls ts desc LIMIT 25; churn commands desc, calls desc LIMIT 25; source bars sorted by count desc.
- Sessions link to `/session?harness=&session=` and carry current filters (`components.tsx:404-421`).
- Time zone: UTC for the daily buckets and the "At (UTC)" column; no Europe/London on this page.
- Not-emitted: sandbox is not emitted by omp or Claude Code; the page hides sandbox UI when any enabled harness lacks it rather than showing zero.
- Empty states: F09 and F10 messages, DataTable default "No rows for the selected range.", chart empty text.
- Bypass subtitle states that command text is not stored; keep (privacy).
- Rejection counts treat every decision not in {approved, approved_with_amendment, accept} as rejected, including empty or unknown decision strings.
