## Behaviours to preserve

- Entry only via URL `harness` and `session` (typically from SessionLink); direct paste works; the harness must be enabled on this machine; session ≤ 256 chars (`SV:423-429`).
- No time-range or harness select on this page; the session id is one harness's id; start/end params are carried but ignored for fetch (`app-data.ts:46`).
- Always live fact views, never snapshots (session can predate the snapshot horizon) (`SV:434-435`).
- Prompt masking: `signal != 'prompt'` filter and blank detail for prompts; only prompt length exists in the fact view (`VQ:453-455`, `003_views.sql:649`). Nothing on the page may reintroduce prompt text.
- Ordering: tasks and calls and signals chronological ASC; usage by input DESC; model calls by calls DESC.
- Limits: 500 rows for tool calls and signals, silent; tables scroll in a 340px box.
- Time display: task start and signal time shown as UTC date-time to the second; tool-call time shows time only.
- Not-emitted handling: null → "—", empty string → "—" in Task type, Error, Command, Failure signature, Targets; "Friction observed" blank when empty.
- Corrected-next shows the correction kind with underscores replaced by spaces.
- Empty-state texts for tasks and signals (explanations of why empty) and the generic text for the other three tables.
- Link-back context: SessionLink carries the current filters, so browser Back restores them.
- Title: document title "Session · Agent introspection" and heading focus on load (baseline `App.tsx:305-308`; not re-verified on this tree).

## Audit notes

- Default empty text "No rows for the selected range." on usage, model-calls and tool-call tables is misleading (no range applies to this page).
- Silent LIMIT 500 on calls and signals understates the head counts and "failed" figure for long sessions; the Tools page counts can exceed what the head shows.
- Fetched but never displayed: tasks.task_id and output_tokens, calls.task_id and duration_ms, signals.turn_id, model_calls.p50 (duration median). Possible dropped signals if a redesign wants them; no UI needs them today.
- Time-zone: `toString(DateTime64)` strings are sliced and labelled UTC; the column time zone was not verified here. The other pages use Europe/London for daily bucketing; this page is not bucketed.
- Session ids are shown in full in the head and cut to 8 characters in links; the full id appears only on this page (identification feature to keep).
- No info notes, harness contribution chips or support states on this page; for a harness that lacks a signal the column simply shows "—", which cannot be told apart from "no data" (not-emitted vs not-applicable lost).
- Task type and corrected-next rely on `task_labels`, which reads the task_outcomes snapshot (`003_views.sql:721`) even on this live-only page: tasks older than 91 days get no labels.
- Joins labels by (harness, session_id) in a subquery, then LEFT JOIN on task_id only (`VQ:437-440`); fine within one session.
- Risk of being dropped: prompt masking (invisible, server-side), the corrected-next kind text, "Friction observed" list, the filter carry-over in links, the empty-state explanation for sessions without a task boundary.

### Fixed 2026-10-01

- Head counts (tasks · tool calls · failed) now come from the uncapped `head_counts` query (`VQ:458-461`, `SS:13-19`); the Tool calls and signals tables pass `total`, so "Showing N of M" appears when LIMIT 500 cuts them. Affects SESS-F02, F06, F07, F13, S14, C02, C03.
- Usage, model-calls and tool-call tables now have session-specific empty texts ("No model usage in this session.", "No model calls in this session.", "No tool calls in this session."). Affects SESS-F04, F05, F06.
