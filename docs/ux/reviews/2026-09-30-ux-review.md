# UX review: Agent Introspection dashboard, 2026-09-30

A review of every page against [`principles.md`](../principles.md) and [`DESIGN.md`](../DESIGN.md), graded
with the `ux-page` rubric ([`../rubrics/ux-page.yaml`](../rubrics/ux-page.yaml)).

**Method.** Each page was captured from the running app at the reference size, 2560 × 1440 (a 2560 × 1330
viewport after browser chrome): the first screen and the full page. The capture used the current working tree,
built and served on a separate local port so the existing server on port 4173 was left alone. Session was
captured with the harness filter set to omp, because it needs one harness. Screenshots and score files stay in
git-ignored `docs/ux/reviews/captures/`. Each criterion was scored against its anchors with citations to screenshots and
`file:line`, and each total was computed by `score_rubric.py`. This document quotes no private data.

**Scope.** Review and backlog only. The only app code changed in this run is the token mirror
(`dashboard/src/tokens.css`, `dashboard/src/tokens.ts`), which `format.ts` now reads; the page renders the same
colours as before.

**No-regression baseline.** [`2026-09-30-feature-inventory.md`](2026-09-30-feature-inventory.md) lists every feature,
signal and calculation with a stable ID and a _New home_ column.

## Verdict

**Every page holds the right data, but none yet leads the reader from its question to a conclusion: ten pages
score Needs work and Session scores Rework.** The shared page structure is the strongest part (2.8 of 3 on
average): every view opens on its question and four headline figures. What drags every page down is shared
presentation, not page logic: a centred 1540px column that leaves a wide gap beside the sidebar, 170px charts,
text at 9–11px with tracked capitals, non-harness series in harness colours, and definitions hidden in
expanding footers or native tooltips (type, charts and layout average 1.0 of 3; terms 0.9). On top of that,
each page spreads its key comparison over separate panels and scales, and small samples are shown at the same
weight as large ones, so analysis support averages 1.6. Fixing the shared foundation first lifts every page at
once.

## Per-page summary

### Cache efficiency (64.0, Needs work)

- **Question and conclusion.** Question: where are tokens consumed and how much input is served from cache. Conclusion: overall utilization (95.8%), which harness/model/session leaks uncached input, and whether it is trending. The KPIs and trend charts give the headline; the drill from headline to cause is across three separate tables (By harness, By model, sessions) whose shares of uncached input are not shown, so a reader must compute which row matters (cache-full.png). Utilization and volume sit on different panels; the utilization lines are not volume-weighted visually, so the Codex exec dip looks as important as omp's volume.
- **Main issues.** (1) Chart readability: 170px charts (charts.tsx:13), uncached slice nearly invisible against cached on a 3B axis, and the series legend uses harness-coloured SERIES[0..2] directly under the harness legend (Cache.tsx:50-54, cache-first.png). (2) Uncached input has no share-of-total or bar so ranking by impact is manual (cache-full.png, Cache.tsx:144-246). (3) Type below 12px and centred 1540px column (styles.css:156-160; table th 9px, ticks 10px).
- **First screen.** Answer: utilization and how much is uncached, and who causes it. L1: four KPIs, daily utilization chart at 280-360px beside a ranked uncached-by-harness bar, all at 2560×1330.
- **Moves.** L2 in place: daily token consumption and By harness table. L3 page: By model and the top sessions table (already drills to sessions).

## Ranked backlog

label or state word (principle A9).
