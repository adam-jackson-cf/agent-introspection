## Uncovered observations

- all pages: the sidebar still lists Findings and fixes; removing the page needs the nav entry and two in-panel links removed with it.
- pipeline: the KPI links "Show loader refresh", "Show source parity" and "Show sanitization" are same-page anchors that look like page links.
- pipeline-coverage: 251 of 265 cells are "healthy", so the grid is a long table of mostly identical green chips; the few non-healthy cells are not sorted or filtered first.
- glossary: a 28,579 px page with no search, filter or jump list, holding raw route and attribute codes (`codex.sse_event`, `gen_ai.usage.input_tokens`) as its primary text.
- session: tool-call targets render full temporary paths, as cell text; the sanitization check counts home paths only.
- all pages: the app is dark-only (`color-scheme: dark` in `dashboard/src/styles.css:2`); the skill scores the light scheme, which renders identically here.

## Detector findings believed to be false positives (reported, not waived)

- G14b on all 12 pages (blocking): the detector looks for contract tones `status-pass|fail|watch|info|unmeasured` in `DESIGN.md`. The app's style (`style: project`) names its tones `status-healthy` and so on, so the item fails on naming before any colour is checked. The cap at 59 on every page comes from this and from D01a.
- G14c on all 12 pages: 25 of the 26 contrast findings are "missing token" (no `border-control`, no `on-status-*` and `-soft` forms, no `series-N`), not a measured ratio below 4.5:1.
- G21a: the 7 colour literals are all in `*.test.tsx` files, which the scan includes. The 125 spacing literals in `styles.css` are real, so the item still fails.
- G14d on 9 pages (245 findings): the overlay put `data-entity` on the harness chip container, whose own background is transparent, so the colour of the swatch inside it was never compared. This is an audit-instrument artefact.
- G12a and G12b on `#root`: React attaches its click handler to the root container; no clickable div is visible on screen. The missing `[tabindex]:focus-visible` rule (G12b) is real.
- D09a and G10a "capture missing: pipeline-checks.before.default" on tools and recurrence: `pipeline-checks` is a proposed, unbuilt L3 page in `pages.md`, which the like-minded rule still pairs with them.
- D13a on pipeline-coverage: the probe counted "possible break" and "stray (explained)" as failed; the detector counts only marks drawn in a failed tone, and no tone is mapped to failed yet (see finding 3).
- G01c on 10 pages: the timing badge is an orphan that the skill keeps rendered until the Step 6 approval, so the item fails in every baseline.
- D07a, D15b and G04a findings in the dom results: they come from the undeclared `open` captures (inline `<details>` expands, not drawers) and are scored `na`.

## Generalisation log

- Data host: this machine's ClickHouse is on another host (`~/.config/agent-introspection/config.toml` `machine.role` points to adams-macbook-pro), so the worktree server returned 503. A local proxy served the worktree's built front end and forwarded `/api/*` to the deployed dashboard. The deployed JS bundle differs from the worktree build (CSS identical), so the audited front end is the worktree's, with the deployed server's data.
- Browser: no browser tool in the session and Playwright's bundled browsers missing; captures used Playwright for Python driving the installed Google Chrome (`channel="chrome"`).
- Live data broke the stability check (counts and "min ago" text moved between captures); the run froze data with a replaying proxy and `page.clock.set_fixed_time`, recorded as `data_for_capture: frozen`.
- Skill: the Step 3 baseline-gate command omits `--overlay`, which `signals_check.py` requires for an overlay capture.
- Skill: the baseline gate fails G01c for orphan rows that the derive path keeps rendered until Step 6, so it cannot exit 0 on a page with an orphan.
- Skill: the capture contract has no state for inline `<details>` expands; `open` is reserved for a drawer.
- Skill: `labels_check.py` cannot read a TypeScript catalogue with a type annotation (`export const HARNESS_LABEL: Record<Harness, string> = {`); rows were copied with `copied_from`.
- Skill: `presentation_forms()` parses the presentation Variants line into the allowed set `{form, trend-line}`, rejecting `trend-dot`.
- Skill: the judge-prompt command in `judged-items.md` omits `--page`, which leaves `<page>` unfilled in the prompt title.
- Skill: overlay entries must carry `q`, so mark-only entries (state chips) need their panel's `q` repeated; the snapshot contract does not say so.
- Skill: `score --judged` needs exactly two answer files, so a one-assessor run cannot score its judged items.
