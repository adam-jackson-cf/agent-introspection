## Approved authority, keys, and materialization

**Approved authority:** the shared runtime is the sole Git-project resolver. It validates the native lifecycle or completion-context envelope, resolves the supplied workspace using Git common-directory semantics, and emits the immutable session-context project tuple. [`otel-producers.md` lines 5–15, 28–41; `.enaible/analyze-root-cause/20260807T105112Z-root-cause-analysis/recommendations.md` R1]

**Canonical association:** the primary association is an exact `(canonical producer, native session ID)` join to accepted context. The keys are namespaced: identical session text from different producers never joins. A unique runtime-resolved completion-context tuple for that exact session may reconcile earlier same-session telemetry; it is never inferred from telemetry and is rejected on an authoritative transition conflict. True `session_start`/`workspace_changed`/`session_end` events separately define interval partitions. This implements the plan's downstream exact-join objective. [`PROJECT_ATTRIBUTION_INVESTIGATION_PLAN.md` §Objective, §Canonical boundary under review, §Phase 4; `.enaible/analyze-root-cause/20260807T105112Z-root-cause-analysis/recommendations.md` R1–R2; `src/agent_introspection/attribution.py:resolve_attribution`]

**Materialization:** `agent.project.*`, activity attribution state/method/evidence, and dashboard project columns are derived projections only. They must be reproducible from the accepted context record and exact association; no projection may resolve, override, or fill project identity. [`PROJECT_ATTRIBUTION_INVESTIGATION_PLAN.md` §Canonical boundary under review, §Phase 1 item 4; `src/agent_introspection/attribution.py:canonical_activity_event_attributes`]

## Installed producer capability rules

A producer is `Supported` only after its **installed** entry point demonstrates native lifecycle/context callback → adapter → shared runtime → Git resolution → accepted ledger/inbox result → source telemetry with the equal native key → exact downstream join → dashboard assignment. Otherwise it is `Blocked`; absent proof is not `Unsupported`. [`PROJECT_ATTRIBUTION_INVESTIGATION_PLAN.md` §Phase 3, Gate 3]

Installed entry-point evidence is required: managed configuration must reference the managed adapter path, and direct adapter invocation alone cannot certify the active hook/extension chain. [`otel-producers.md` §Managed installation and configuration, §Validation; `PROJECT_ATTRIBUTION_INVESTIGATION_PLAN.md` findings C8, §Phase 3]

Current capability boundaries are: Claude requires hook/source identity equality, source ingestion, and an installed `CwdChanged` decision; Codex CLI requires persistent-notify-chain proof that completion context is a unique exact-session mapping rather than a false start; app-server needs separate installed protocol proof; Codex app cannot inherit app-server proof; OMP requires installed extension proof that `getSessionId()` equals eligible `gen_ai.conversation.id`. [`PROJECT_ATTRIBUTION_INVESTIGATION_PLAN.md` §Producer status requiring proof, §Phase 3 producer-specific gates; `.enaible/analyze-root-cause/20260807T105112Z-root-cause-analysis/recommendations.md` R1–R3] |

## Gate 1 decision and remaining obligations

**Decision: APPROVED.** The canonical authority is runtime-resolved immutable session context; association is the exact producer plus native session-ID join. True native lifecycle events retain half-open effective-time interval partitioning, while a unique late completion-context mapping may reconcile earlier same-session telemetry without creating a start or interval. Project fields on activities/dashboard rows are reproducible materialized projections only. Producer proof gaps do not reopen this authority decision.
