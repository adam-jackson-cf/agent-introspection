# Project-attribution Gate 3 installed capability decision

## Decision and evidence boundary

**Decision: APPROVED — installed capability classification only.** Every required cell below is classified `Supported` or `Blocked`; `Blocked` means evidence is missing or the installed boundary could not be exercised, **not** `Unsupported`. This decision does not approve implementation, configuration, source, ledger, dashboard, local, or remote mutation.

Gate 1 fixes the authority as an exact, namespaced `(producer, native session ID)` association to runtime-resolved immutable context; dashboard fields are derived projections, not another resolver. [Gate 1, “Approved authority, keys, and materialization”] Gate 2 approved only the frozen, reproducible population and explicitly did not certify producer support. [Gate 2, lines 3–9, 35] Gate 3 evidence is post-cutoff only: cutoff `2026-08-07T17:45:58.546340000Z`. It retains only the allowlisted identities, timestamps, project tuples, statuses, counts, checksums, and presence checks. [`project-attribution-gate-3-{claude,codex-cli,codex-app-server,codex-app,omp}.json` `evidence_policy`; `project-attribution-gate-3-failures.json` `evidence_policy`]

A `Supported` lifecycle/context cell proves only its stated installed-path boundary. Producer support through source, exact join, and dashboard requires the whole Gate 1 chain; no source, join, or dashboard cell is inferred from a callback, matching text in another service, or evidence from another producer namespace.

## Common installed-boundary failure evidence

The common artifact gives bounded installed-adapter behavior without expanding producer support. For Claude and Codex CLI it records malformed-envelope rejection (exit 64), non-Git rejection (exit 65 with no project tuple), runtime rejection (exit 65), and duplicate delivery idempotence (two successful deliveries with identical retained artifact checksum). Unsupported transition is rejected (exit 64). These are exact adapter-boundary outcomes; they do not prove the CLI's active notify invocation, a source identity, an exact producer join, or a dashboard assignment. App-server failure scenarios are blocked because its installed adapter is absent; OMP scenarios are blocked because no callback was executed after the integrity anomaly. ## Phase 7 stop condition

**Triggered: yes.** The plan requires stopping before implementation when an installed producer cannot expose a source identity equal to its context identity. Claude has no qualifying `claude-code` source namespace; Codex CLI and app-server have no executed native/context identity; Codex app has no accessible native identity or source record; and OMP has no safely executable callback. The other stop-condition bases are not re-decided here. Therefore Gate 3 approval preserves the classification and blockers only; it is not Phase 7 implementation or mutation approval.
