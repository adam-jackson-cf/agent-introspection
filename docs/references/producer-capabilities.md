# Producer capabilities

This is the "what to look for" reference for onboarding a producer, whether the
registry already knows it as a harness or not (opencode, or any other agent
harness). Each dashboard signal consumes some kinds of producer data, called
capabilities. For each capability, this page says what to find in the producer, how
to check it, and which signals need it. Parity is strict: a producer is enabled only
when every signal it cannot reach is acceptable to hide, so check its capabilities
before enabling it.

The signal registry (`src/agent_introspection/facts_sql/signal_support.toml`)
declares the capabilities and the ones each harness-scoped signal `requires`. A
harness profile (`src/agent_introspection/harness_profiles/<key>.toml`) records the
status of every capability for one producer, with the route and evidence behind it:

- `native`: in the producer's own telemetry now;
- `hook`: an installed activity hook supplies it;
- `hook_available`: a documented hook or plugin surface exists, but no adapter yet;
- `missing`;
- `not_applicable`;
- `unverified`.

A signal is reachable when every capability it requires is `native` or `hook`. It is
reachable with work when the rest are `hook_available`, unknown when one is
`unverified`, unreachable when one is `missing`, and not applicable when one is
`not_applicable`.

The hints are case-insensitive regular expressions matched against an unknown
producer's span names, event names, and attribute keys, to guess which capabilities
it has. A match is a lead to check, not evidence. Inspect key names and counts only;
never print prompts, commands, or secrets.

The rest of this page is generated by `scripts/render-measures.py` from the registry
and the profiles; edit those, not this page.

## Capabilities

### Telemetry export (`export`)

- **Need:** OTLP export to the local collector with a stable `service.name`.
- **Check:** After a short session, SigNoz holds spans or logs under one `service.name` that no other producer reports.
- **Span names:** none
- **Event names:** none
- **Attribute keys:** `^service\.name$`, `^service\.version$`, `^telemetry\.sdk\.`
- **Required by:**
  - Pipeline: Fact freshness (`pipeline.freshness`), Source parity (`pipeline.parity`)

### Session identity (`session_identity`)

- **Need:** A session key, stable across the session's usage, task, and tool rows.
- **Check:** The same value is on the usage, task, and tool rows of one session, and equals the session ID in the producer's session store.
- **Span names:** none
- **Event names:** none
- **Attribute keys:** `(^|\.)session[._]?id$`, `(^|\.)conversation[._]?id$`, `(^|\.)thread[._]?id$`
- **Required by:**
  - Pipeline: Project attribution (`pipeline.project_attribution`)
  - Cache efficiency: Usage-active sessions (`usage.active_sessions`)
  - Friction: Quick follow-up (`friction.quick_follow_up`), Clean completion (`friction.clean_completion`)
  - Recurring failures: Project concentration (`recur.project_concentration`)
  - Requests and corrections: Labelled tasks (`intent.labelled`), Task type (`intent.task_type`), Corrected by the next prompt (`intent.corrected`), Correction kinds (`intent.correction_kind`), Frustrated follow-ups (`intent.frustration`), Effort payoff by task type (`intent.effort_payoff`)

### Task boundary (`task_boundary`)

- **Need:** One span or event per user turn or run, with start and end.
- **Check:** One per submitted prompt, with a duration, carrying the session key; subagent runs are told apart from the user's turns.
- **Span names:** `turn`, `interaction`, `^invoke_agent$`, `session_?task`, `agent[._]?run`, `prompt\.(loop|run)$`
- **Event names:** `turn`, `interaction`, `agent_(start|end)`
- **Attribute keys:** `(^|\.)turn[._]?id$`, `(^|\.)prompt[._]?id$`, `interaction`
- **Required by:**
  - Pipeline: Project attribution (`pipeline.project_attribution`)
  - Reasoning effort: Tasks (`task.count`), Heavy-effort task share (`effort.heavy_share`), Task duration (`task.duration`), Model steps per task (`task.model_steps`), Reasoning tokens per task (`task.reasoning_tokens`), Delegations per task (`task.delegations`)
  - Tool failures: Tasks affected by failures (`tools.tasks_affected`), Repeated attempts (`tools.repeats`), Tool loops (`tools.loops`)
  - Friction: Interrupted tasks (`friction.interrupt`), Steered tasks (`friction.steer`), Errored tasks (`friction.error`), Quick follow-up (`friction.quick_follow_up`), Clean completion (`friction.clean_completion`), Recovery after failure (`friction.recovery`)
  - Verification and guardrails: Command churn (`guard.command_churn`), Failures caught in the task (`guard.verification_caught`)
  - Recurring failures: Recurring targets (`recur.targets`), Recurring failure signatures (`recur.signatures`), Actionable repeats (`recur.actionable`)
  - Requests and corrections: Labelled tasks (`intent.labelled`), Task type (`intent.task_type`), Corrected by the next prompt (`intent.corrected`), Correction kinds (`intent.correction_kind`), Frustrated follow-ups (`intent.frustration`), Effort payoff by task type (`intent.effort_payoff`)

### Model usage (`model_usage`)

- **Need:** Per-call input, cached-input, and output tokens (cache creation if present).
- **Check:** Per-call token sums over a session match the producer's own accounting, and cached input is reported apart from input.
- **Span names:** `^chat\b`, `llm`, `completion`, `sampling`, `generate`
- **Event names:** `api_request`, `response\.completed`, `sse_event`, `usage`
- **Attribute keys:** `^gen_ai\.usage\.`, `token`, `cache_?(read|creation|write)`, `cached`
- **Required by:**
  - Pipeline: Source parity (`pipeline.parity`)
  - Cache efficiency: Input tokens (`usage.input_tokens`), Cached input (`usage.cached_input`), Uncached input (`usage.uncached_input`), Cache creation (`usage.cache_creation`), Output tokens (`usage.output_tokens`), Input cache utilization (`usage.cache_utilization`), Completed operations (`usage.operations`), Usage-active sessions (`usage.active_sessions`)
  - Reasoning effort: Reasoning share of output (`effort.reasoning_share`)
  - Provider: Output throughput (`provider.throughput`)

### Reasoning usage (`reasoning_usage`)

- **Need:** Reasoning or thinking tokens.
- **Check:** A per-call or per-turn reasoning token count that is part of the output tokens, and 0 rather than absent when a model does not reason.
- **Span names:** none
- **Event names:** none
- **Attribute keys:** `reasoning.*token`, `thinking.*token`, `token.*reasoning`
- **Required by:**
  - Reasoning effort: Reasoning tokens (`effort.reasoning_tokens`), Reasoning share of output (`effort.reasoning_share`), Reasoning tokens per task (`task.reasoning_tokens`)

### Model and effort (`model_identity`)

- **Need:** The served model and the requested reasoning effort.
- **Check:** Model and effort values on the model-call or task rows; the served model is reported apart from the requested one.
- **Span names:** none
- **Event names:** none
- **Attribute keys:** `^gen_ai\.(request|response)\.model$`, `(^|[._])model([._]?id)?$`, `effort`
- **Required by:**
  - Reasoning effort: Requested effort (`effort.level`), Heavy-effort task share (`effort.heavy_share`)
  - Provider: Model conformance (`provider.model_conformance`)
  - Requests and corrections: Effort payoff by task type (`intent.effort_payoff`)

### Model call outcome (`model_outcome`)

- **Need:** Per-call status or error, latency, time to first token, retries.
- **Check:** Failed calls carry an error status or message, a user cancellation is told apart from a failure, calls have a duration and time to first token, and a retry is told apart from a first attempt.
- **Span names:** `^chat\b`, `llm`, `sampling`
- **Event names:** `api_error`, `retr`, `response\.completed`
- **Attribute keys:** `ttft`, `time_to_first`, `finish_reason`, `stop_reason`, `(^|\.)attempt`, `retr`, `^error\.`, `(^|\.)status`, `(^|\.)success$`
- **Required by:**
  - Reasoning effort: Model steps per task (`task.model_steps`)
  - Friction: Errored tasks (`friction.error`)
  - Provider: Model calls (`provider.calls`), Call error rate (`provider.error_rate`), Stream disconnects (`provider.stream_disconnects`), Model call latency (`provider.latency`), Time to first token (`provider.ttft`), Output throughput (`provider.throughput`), Retries (`provider.retries`), Unknown outcomes (`provider.unknown_outcomes`)

### Tool calls (`tool_calls`)

- **Need:** One row per tool call: name, call ID, outcome, joinable to its task.
- **Check:** One row per call with the tool name and a success, failure, or abort outcome, joinable to its task by trace, or by session and time.
- **Span names:** `tool`
- **Event names:** `tool`
- **Attribute keys:** `tool[._]?name$`, `tool[._]?call[._]?id$`, `tool_use_id`, `^gen_ai\.tool\.`
- **Required by:**
  - Tool failures: Tool calls (`tools.calls`), Tool failure rate (`tools.failure_rate`), Failure signature (`tools.failure_signature`), Tasks affected by failures (`tools.tasks_affected`), Repeated attempts (`tools.repeats`), Tool loops (`tools.loops`)
  - Friction: Recovery after failure (`friction.recovery`)
  - Verification and guardrails: Quality-gate bypass (`guard.gate_bypass`), Command churn (`guard.command_churn`), Verification runs (`guard.verification`), Failures caught in the task (`guard.verification_caught`)
  - Recurring failures: Recurring targets (`recur.targets`), Recurring failure signatures (`recur.signatures`), Actionable repeats (`recur.actionable`), Project concentration (`recur.project_concentration`)

### Tool argument identity (`tool_arguments`)

- **Need:** Argument identity (hashable arguments or command) without storing text.
- **Check:** Each call's arguments or command reach the producer's telemetry or a hook, so an argument hash and command shape can be derived; the text itself is never stored.
- **Span names:** none
- **Event names:** `tool_call`, `pre_?tool`, `tool\.execute\.before`
- **Attribute keys:** `argument`, `(^|[._])args?$`, `tool[._]?input`, `(^|[._])command$`
- **Required by:**
  - Tool failures: Repeated attempts (`tools.repeats`), Tool loops (`tools.loops`)
  - Friction: Recovery after failure (`friction.recovery`)
  - Verification and guardrails: Quality-gate bypass (`guard.gate_bypass`), Command churn (`guard.command_churn`), Verification runs (`guard.verification`), Failures caught in the task (`guard.verification_caught`)
  - Recurring failures: Recurring targets (`recur.targets`)

### Tool failure diagnostic (`tool_failure`)

- **Need:** A diagnostic line for a failed call.
- **Check:** A failed call's error text reaches the telemetry or a hook, so one normalized diagnostic line can be taken from it.
- **Span names:** none
- **Event names:** `tool_failure`, `tool_?use_?failure`, `tool_result`
- **Attribute keys:** `^error\.(message|type)$`, `failure`, `exit_code`, `status_message`, `stderr`, `(^|[._])error$`
- **Required by:**
  - Tool failures: Failure signature (`tools.failure_signature`)
  - Recurring failures: Recurring failure signatures (`recur.signatures`), Actionable repeats (`recur.actionable`), Project concentration (`recur.project_concentration`)

### User friction (`user_friction`)

- **Need:** Interrupts, steers, follow-ups.
- **Check:** An interrupted task is told apart from an errored one, input sent while a task runs is visible, and the next task of a session can be found; a headless surface has no user, so it is not applicable there.
- **Span names:** `interrupt`, `steer`, `abort`, `cancel`
- **Event names:** `interrupt`, `steer`, `abort`, `cancel`, `prompt_submit`
- **Attribute keys:** `interrupt`, `abort`, `cancel`, `steer`
- **Required by:**
  - Friction: Interrupted tasks (`friction.interrupt`), Steered tasks (`friction.steer`), Quick follow-up (`friction.quick_follow_up`), Clean completion (`friction.clean_completion`)
  - Requests and corrections: Corrected by the next prompt (`intent.corrected`), Correction kinds (`intent.correction_kind`), Frustrated follow-ups (`intent.frustration`), Effort payoff by task type (`intent.effort_payoff`)

### Approvals and sandbox (`approvals`)

- **Need:** Approval or permission decisions, and sandbox outcomes.
- **Check:** Each decision records approve or reject and who decided (configuration or user); each sandboxed command records its outcome.
- **Span names:** `permission`, `approv`
- **Event names:** `decision`, `approv`, `permission`, `sandbox`
- **Attribute keys:** `decision`, `approv`, `permission`, `sandbox`
- **Required by:**
  - Verification and guardrails: Tool approval decisions (`guard.decisions`), Rejected tool calls (`guard.rejections`), Sandbox outcomes (`guard.sandbox`)

### Delegation (`delegation`)

- **Need:** Subagent spawns.
- **Check:** One record per subagent start, joinable to the task that started it.
- **Span names:** `^invoke_agent .`, `subagent`, `spawn`, `delegat`
- **Event names:** `subagent`, `spawn`, `agent_communication`, `delegat`
- **Attribute keys:** `parent[._]?(session|thread|conversation)`, `subagent`, `sender_thread`
- **Required by:**
  - Reasoning effort: Delegations per task (`task.delegations`)

### Prompt text (`prompt_text`)

- **Need:** A prompt event carrying text, for prompt labels.
- **Check:** One event per submitted prompt with its text (not a redaction placeholder) once prompt export is on, joinable to the task it starts.
- **Span names:** none
- **Event names:** `user_prompt`, `prompt`
- **Attribute keys:** `(^|[._])prompt$`, `prompt[._](text|length)`, `user_prompt`
- **Required by:**
  - Requests and corrections: Labelled tasks (`intent.labelled`), Task type (`intent.task_type`), Corrected by the next prompt (`intent.corrected`), Correction kinds (`intent.correction_kind`), Frustrated follow-ups (`intent.frustration`), Effort payoff by task type (`intent.effort_payoff`)

### Session store (`session_store`)

- **Need:** A local store mapping session ID to working directory.
- **Check:** On disk, not in telemetry: a file or database record holding the session ID and the absolute working directory, whose ID equals the telemetry session key (becomes a `session_stores.toml` entry).
- **Span names:** none
- **Event names:** none
- **Attribute keys:** none
- **Required by:**
  - Pipeline: Project attribution (`pipeline.project_attribution`)
  - Recurring failures: Project concentration (`recur.project_concentration`)
